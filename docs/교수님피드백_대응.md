# 교수님 피드백 대응 현황 (2026-10-13 기준)

중간 발표(10/7) 후 받은 피드백과, 무엇을 적용했고 무엇을 못 했는지(이유 포함) 정리합니다.

## 한눈에 보기

| 피드백 | 상태 | 요약 |
|---|---|---|
| ① 직방 앱에서 방 정보를 크롤링해 자동 입력 | ⏸ 대안으로 변경 (6~7주차 예정) | 크롤링 대신 **매물 화면 캡처·복사 붙여넣기 자동 입력** |
| ② 허위매물·거래 완료 여부 같은 실시간 정보 | △ 부분 적용 | 거래 완료 여부는 공개 데이터가 없음 → **미끼매물 의심 경고 + 계약 전 확인 4가지** |
| ③ 실시간 데이터, 데이터 유지 | △ 부분 적용 | **웹 배포**, 성적표 **최근 6개월 자동 이동**, 부동산원 전환율 연결 / 월 1회 자동 갱신(GitHub Actions)은 3주차 |
| ④ (팀 의견) 기능을 더 붙이기 | ✅ 적용 | **예산으로 찾기**, **보증금 바꾸면?**, **건축물대장(연립다세대)** |

## ① 크롤링 자동 입력 → 캡처 자동 입력으로 변경

- **못 한 이유**
  - 국내 판례에서 크롤링은 형사 무죄가 나도 민사 배상 위험이 큼: 여기어때(야놀자 정보 크롤링) 민사 10억 원, 사람인(잡코리아 공고 크롤링) 2심 2.5억 원.
  - 직방이 차단하거나 내부 구조를 바꾸면 서비스가 바로 멈춤 → "데이터 유지"와도 맞지 않음.
  - 직방 이용약관은 우리 환경에서 확인하지 못함.
- **대안:** 사용자가 직방·다방·네이버 매물 화면을 캡처하거나 설명을 붙여넣으면 AI가 동·면적·보증금·월세·층·준공연도를 채움. 우리 서버가 직방에 접속하지 않아 법적 위험이 거의 없고, 여러 앱에 똑같이 쓸 수 있음.
- **남은 문제:** 이미지를 읽는 LLM API는 유료일 수 있음 → 비용 주체를 팀에서 정해야 시작 가능.

## ② 허위매물·거래 완료 여부

- **못 한 이유:** 매물이 팔렸는지는 직방·다방·네이버 같은 플랫폼만 알고 공개 데이터가 없음. 국토부 대학가 광고 단속(2025.10, 321건 적발)도 건수·유형만 공개하고 매물 목록은 비공개. 공공데이터는 계약이 끝난 실거래뿐.
- **적용한 것**
  - **미끼매물 의심 경고:** AI 예상 중앙값의 0.65배 이하(보증금 3,000만 원 이하)면 경고. 허위매물 정답 데이터가 없어 "진짜 거래에 경고가 잘못 뜨는 비율"을 약 2%로 맞춤 (notebooks/08).
  - **계약 전 확인 4가지:** 방이 지금도 있는지, 전용면적, 옵션, 관리비. 국토부 단속 적발 유형(부당표시 52% — 면적 과장·없는 옵션·계약 끝난 매물, 명시의무 위반 48% — 관리비 누락)에서 가져옴.

## ③ 실시간 데이터·데이터 유지

- **적용한 것**
  - Streamlit Community Cloud 웹 배포 (링크로 누구나 사용)
  - 예측 성적표가 데이터의 **가장 최근 6개월**로 자동 시험 (마지막 1개월은 신고 지연으로 제외)
  - 한국부동산원 전월세 전환율(월간 통계) 연결
- **아직 못 한 것:** GitHub Actions로 매달 1일 최근 3개월치 자동 재수집 → 3주차.
- **왜 '일 단위 실시간'이 아니라 '월 단위'인가:** 실거래는 계약 후 30일 이내 신고라 최근 1~2개월이 늘 덜 들어와 있음. 매일 받아도 새로 늘어나는 정보가 적어서 월 1회가 이 데이터에 맞는 주기.

## ④ 기능 추가

| 기능 | 근거 |
|---|---|
| 예산으로 찾기 (동·유형·면적 추천) | 과거 1년으로 추천 → 다음 6개월 확인: 추천 조합 64%가 예산 안 vs 같은 예산 전체 45% (notebooks/09) |
| 보증금 바꾸면? | 한국부동산원 인천 전환율(연립 8.84%·단독 9.19%·오피스텔 40㎡이하 7.30%) + 법정 상한 5.0% 참고. 같은 건물 거래 비교로도 약 8% (notebooks/10) |
| 건축물대장 (연립다세대) | 시험 125건 평균 오차 5.77 → 4.76만 원 (팀 합의 문서 참고) |
