# 사용자 테스트 계획 (React 버전, 3명 × 15분)

2차 중간발표에서 "학생 3~6명 테스트"를 약속했고, 교수님 피드백 3가지가 모두 **사용성** 문제라서
"새 화면이 정말 편한가"를 숫자로 보여 주는 게 목적이다. 짧게, 대신 **기록은 꼼꼼히**.

## 누구를
- 우리 팀이 아닌 학생 3명 (자취 중이거나 방을 구해 본 사람 2명 이상)
- 서비스 설명은 하지 않는다. "방 구할 때 쓰는 사이트예요" 한 마디만.

## 준비물
- PC 한 대: 직방 웹(원룸) 탭 + 적정월세 배포 주소 탭
- 타이머(휴대폰), 아래 기록표 인쇄 또는 노트북
- 시작 전 북마크 비우기 (브라우저 시크릿 창을 쓰면 편함)

## 과제 (말로 읽어 주기, 순서대로)

| # | 과제 | 성공 기준 | 기록 |
|---|---|---|---|
| 1 | "직방에서 인하공전 근처 원룸 하나를 골라서, 이 사이트로 월세가 적당한지 확인해 주세요." | 진단 결과(저렴/적정/비쌈)를 말함 | 걸린 시간, 막힌 곳 |
| 2 | "다른 방 하나를 더 확인하고, 두 방 중 어디가 나은지 비교해 주세요." | 북마크 비교 화면에서 답함 | 걸린 시간, 북마크를 스스로 찾았나 |
| 3 | "보증금을 1,000만 원 더 내면 월세가 얼마가 되는지 알아봐 주세요." | 숫자를 말함 | 걸린 시간 |
| 4 | "보증금 300, 월세 35로 구할 만한 동을 찾아 주세요." | 동 이름을 말함 | 걸린 시간 |

- 진행자는 **도와주지 않는다.** 2분 넘게 막히면 힌트 한 번 주고 "힌트 사용"으로 기록.
- 참가자가 생각을 소리 내어 말하게 한다 ("지금 뭘 찾고 계세요?").

## 끝나고 물어볼 것 (5점 척도 + 한 줄)

1. 붙여넣기로 값이 채워지는 게 편했나요? (1 불편 ~ 5 편함) / 불편했다면 어디가?
2. 결과(범위·저렴/적정/비쌈)를 믿을 수 있었나요? (1~5) / 왜?
3. 두 방 비교 화면이 결정에 도움이 됐나요? (1~5)
4. 실제로 방을 구할 때 다시 쓸 것 같나요? (1~5)
5. 하나만 고친다면 무엇을?

## 기록표 (참가자마다 한 장)

| 항목 | 참가자 A | 참가자 B | 참가자 C |
|---|---|---|---|
| 과제1 시간 / 성공 / 힌트 | | | |
| 과제2 시간 / 성공 / 힌트 | | | |
| 과제3 시간 / 성공 / 힌트 | | | |
| 과제4 시간 / 성공 / 힌트 | | | |
| 붙여넣기에서 못 읽은 값 | | | |
| 질문 1~4 점수 | | | |
| 질문 5 (한 줄) | | | |

## 발표에 쓰는 법
- "3명 중 N명이 도움 없이 과제1을 M분 안에 끝냄", "붙여넣기 편의성 평균 X점"처럼 **숫자 + 인용 한 줄**.
- 못 읽은 값이 나오면 그 글자를 `tests/test_listing_parser.py`에 예시로 추가하고 파서를 고친다 → "테스트로 찾은 문제를 이렇게 고쳤다"가 발표 근거가 된다.
- 3명은 통계가 아니라 **문제 찾기용**이라는 점을 발표에서 먼저 밝힌다(교수님 질문 대비).
