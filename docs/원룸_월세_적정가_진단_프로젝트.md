# 원룸 월세 적정가 진단 — 프로젝트 소개

> 투표로 확정 · 작성일 2026-10-06 · "확인 필요" 표시는 아직 사실 확인이 안 된 내용입니다.

## 1. 한 줄 소개

주소(동), 면적, 층, 보증금·월세를 넣으면 "이 방이 주변 시세보다 비싼지"를 예측 범위와 함께 알려주는 웹 서비스입니다.

## 2. 해결하려는 문제

- 원룸·다가구는 아파트와 달리 시세를 알기 어렵습니다. 보증금과 월세 조합이 제각각이라 비교는 더 어렵습니다.
- 정부의 안심전세앱은 전세 사기 위험 진단이 중심입니다. "이 월세가 적정한가"에는 답하지 않습니다.
- 대학생은 처음 방을 구하는 경우가 많아, 비싼 계약을 해도 알아채기 어렵습니다.

## 3. 누구를 위한 서비스인가

- 1차: 학교 근처 원룸을 구하는 대학생, 사회초년생
- 검토 중: 같은 예산으로 다른 동네까지 비교하고 싶은 사람

## 4. 핵심 기능

| 우선순위 | 기능 | 설명 |
|---|---|---|
| 필수 | 적정가 예측 | 동·면적·층·준공연도 기준으로 적정 월세 범위를 예측 |
| 필수 | 가격 신호 | 입력한 가격을 "저렴 / 적정 / 비쌈" 신호등으로 표시 |
| 필수 | 예측 성적표 | 모델 예측이 실제 거래와 얼마나 맞았는지 화면에 공개 |
| 추가 | 조건 환산 | "보증금을 500만 원 올리면 적정 월세는 얼마?"처럼 보증금·월세를 바꿔 비교 |
| 추가 | 쉬운 설명 | AI가 "왜 비싸다고 봤는지"를 근거 거래와 함께 한두 문장으로 설명 |
| 선택 | 계약 체크리스트 | 계약 전 확인할 것 목록, 전세라면 안심전세앱으로 연결 |

필수 기능 세 개를 먼저 완성하고, 추가·선택 기능은 그 뒤에 붙입니다.

## 5. 다른 서비스에서 참고한 기능

| 참고한 서비스 | 가져올 기능 | 우리 방식으로 바꾼 점 |
|---|---|---|
| 안심전세앱 (HUG) | 안전·주의·위험 3단계 표시 | 사기 위험이 아니라 가격 적정성을 3단계로 표시 |
| 국토부 실거래가공개시스템 | 지역별 전월세 거래 목록 | 목록 대신 예측 범위로 가공 |
| ziplife-navi (오픈소스) | 자치구 평균 시세와 비교 | 구 평균이 아니라 동·면적·층을 반영한 예측 |

## 6. 우리만의 차별점

1. 전세 사기가 아니라 월세 적정가에 답합니다.
2. 숫자 하나가 아니라 "이 범위면 적정"이라는 예측 구간을 보여줍니다.
3. 예측이 얼마나 맞았는지 성적표를 공개합니다.

## 7. 사용할 데이터와 기술

| 구분 | 내용 |
|---|---|
| 거래 데이터 | 국토부 전월세 실거래가 API 3종: 단독/다가구, 연립다세대, 오피스텔 (공공데이터포털, 무료) |
| 건물 정보 | 국토부 건축물대장 API (준공연도, 구조 등, 필드 확인 필요) |
| 지역 코드 | 법정동 코드표 (API 요청에 시군구 코드 5자리가 필요) |
| 예측 모델 | 동 중앙값 기준선 → XGBoost / LightGBM → 예측 구간(분위수 회귀) 순서로 비교 |
| 화면 | Streamlit 웹 |
| 설명 문장 | LLM API (근거 거래 데이터를 넣어주고 설명 문장만 생성) |

**용어 풀이**

- 기준선: "같은 동, 비슷한 면적 거래의 중앙값"처럼 가장 단순한 예측입니다. 우리 모델이 이것보다 나은지를 비교합니다.
- 분위수 회귀: 값 하나가 아니라 "하위 10%~상위 90% 범위"처럼 구간을 예측하는 방법입니다.
- 시간 분할 검증: 과거 거래로 학습하고 최근 거래로 시험하는 방식입니다. 무작위로 섞으면 미래 정보가 학습에 섞여 성능이 부풀려집니다.

## 8. 경쟁 서비스 비교 (10/6 직접 확인)

| 서비스 | 하는 일 | 우리와 겹치는가 |
|---|---|---|
| 안심전세앱 (HUG) | 매매시세 조회, 전세보증금 기준 위험진단 | 겹치지 않음. 월세 입력 칸이 없고, 챗봇도 "시세조회는 매매시세, 위험진단은 전세계약"이라고 답함 |
| 직방 매물 화면 | 호가, 관리비, 면적, 층 표시 | 겹치지 않음. "주변 시세 대비" 판단 표시는 없음 |
| 직방 AI중개사 | 대화형으로 "비싼가"에 답함 | **일부 겹침.** "아주 비싼 편은 아니다, 일반 시세 300~500/30~40"이라고 답했지만 근거 거래·건수가 없고 "실제와 차이가 있을 수 있다"는 안내가 붙음 |
| 다방, 네이버부동산 | 확인 필요 | 확인 필요 |

**그래서 우리 차별점은** "실제 계약 근거 + 숫자로 된 범위 + 정확도 공개"입니다.

시연 사례: 직방 매물(용현동 16㎡, 300/32)과 비슷한 실제 계약 120건(용현동, 13~19㎡, 보증금 200~500, 신규)의 월세 중앙값은 39만 원이었고, 32만 원은 하위 21%였습니다. 직방은 "비싸지 않다"고만 했고, 우리는 근거와 위치를 숫자로 보여줄 수 있습니다.

## 9. 약점

### 아직 남은 약점

| 약점 | 영향 | 대응 |
|---|---|---|
| 관리비·옵션·역 거리 정보가 없음 | 월세를 낮추고 관리비를 올린 방을 "저렴"으로 잘못 볼 수 있음 | 화면에 "관리비 별도" 표시, 사용자가 관리비를 입력하면 합계도 보여주기 |
| 단독/다가구는 층·지번이 없음 | 같은 동 안에서 위치·층 차이를 반영 못함 | 층은 있는 유형만 사용, 없으면 빈칸으로 학습 |
| 신고되지 않은 소액 계약은 일부만 들어옴 | 아주 싼 방은 예측이 덜 정확할 수 있음 | 보고서와 화면에 한계로 명시 |
| 최근 1~2개월은 신고가 덜 들어옴 | 최신 시세가 늦게 반영됨 | 시험 데이터에서 마지막 달 제외 |
| 직방 AI중개사와 일부 겹침 | "직방 보면 되지 않냐"는 질문 | 근거·범위·정확도로 차별화 (8번 참고) |
| 자주 쓰는 서비스는 아님 | 방은 1~2년에 한 번 구함 | 수업 프로젝트로서는 감수 |

### 확인해서 해결된 것

| 걱정했던 것 | 확인 결과 (미추홀구 12개월 데이터, 10/6) |
|---|---|
| 안심전세앱과 겹칠 수 있다 | 겹치지 않음 (8번 표 참고) |
| 단독/다가구의 "연면적"이 건물 전체 면적일 수 있다 | 중앙값 35㎡(다가구 32㎡)로, 방(계약) 면적으로 쓸 수 있음 |
| 월세 30만 원 이하 소액 계약이 빠질 수 있다 | 원룸 거래의 17%가 소액 계약으로 들어 있음 |
| 데이터가 너무 적을 수 있다 | 원룸(33㎡ 이하, 신규)만 1년에 1,699건, 용현동만 920건 |

## 10. 개발 전 준비 체크리스트

### 팀이 정할 것

- [ ] 대상 지역 2~3개 구 (예: 학교가 있는 구와 주변 구)
- [ ] 대상 주택 유형: 단독/다가구, 연립다세대, 오피스텔 중 무엇을 넣을지
- [ ] 예측 대상 정의: 월세만 예측할지, 보증금을 월세로 환산한 "월 환산 비용"을 예측할지
- [ ] 수집 기간 (예: 최근 3년)
- [ ] 성공 기준 (예: 기준선 대비 오차 몇 % 감소)
- [ ] 역할 분담

### 신청·준비할 것

- [ ] 공공데이터포털 회원가입 (팀원 전원, 트래픽을 나눠 쓰기 위해)
- [ ] 전월세 실거래가 API 3종 활용신청
- [ ] 건축물대장 API 활용신청
- [ ] 법정동 코드표 내려받기
- [ ] LLM API 키 (예산 확인)
- [ ] GitHub 저장소, Colab 공유 폴더(Google Drive) 만들기

### 확인할 것

- [ ] API 샘플 호출로 실제 응답 항목 이름 확인 (보증금, 월세, 면적, 층, 건축년도, 지번 공개 범위)
- [ ] 대상 지역에서 1년치 거래가 몇 건인지, 월세 30만 원 이하 거래가 있는지
- [ ] 안심전세앱 직접 설치해 월세 관련 기능 확인
- [ ] 직방, 다방, 네이버부동산의 원룸 시세 기능 확인 (캡처해 두기)
- [ ] 교수님 평가 기준 확인
- [ ] 학생 5~10명 설문: "방 구할 때 시세를 어떻게 확인했나요?", "계약 후 비싸게 계약했다고 느낀 적 있나요?"

### 공부할 것

- [ ] Python requests로 API 호출, XML·JSON 응답 읽기
- [ ] pandas 기초 (불러오기, 걸러내기, 묶어서 평균 내기)
- [ ] XGBoost / LightGBM 기본 사용법
- [ ] 시간 분할 검증, MAE·MAPE 의미
- [ ] Streamlit 기초
